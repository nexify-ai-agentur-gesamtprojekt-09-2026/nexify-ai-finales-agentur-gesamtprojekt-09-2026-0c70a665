# Entscheidung — Sentry als Betriebsüberwachung (2026-10-27)

## Auftrag
Betrieblicher Dauerbetrieb für Sentry, rückwirkend auf die gesamte App.

## Ist
Keine Fehlerüberwachung aktiv. Drei Sentry-Projekte vorhanden, 0 offene Issues.
Deployte Oberfläche: `apps/site` (Vite, Vercel). Serverfunktionen: `api/agent-chat.ts`, `api/agent-runtime-status.ts`.

## Entscheidung
1. Browser: `@sentry/react` in `apps/site/src/observability.ts`, DSN über `VITE_SENTRY_DSN` zur Build-Zeit.
2. Server: `@sentry/node` in `packages/observability/sentry-server.ts`, DSN über `SENTRY_DSN` zur Laufzeit.
3. Ohne DSN bleibt alles inaktiv (No-Op), damit Builds und Vorschauen ohne Konfiguration laufen.
4. `dataCollection.userInfo: false`, `tracesSampleRate: 0` — keine PII, keine Performance-Daten.
5. Nur unerwartete Serverfehler werden gesendet; erwartete `InputError`/`AccessError` bleiben draußen.

## Nicht enthalten
- `apps/web` (Next.js-Referenz, nicht deployt) — wird bei Deployment nachgezogen.
- Source-Maps-Upload, Session-Replay, Performance-Tracing, Alerting-Regeln.

## Zuordnung
| Bereich | Projekt | DSN-Variable |
|---|---|---|
| Browser `apps/site` | nex2fly / sentry-bistre-cable | `VITE_SENTRY_DSN` |
| API `api/*` | nexify-chat-it-automate-it / javascript-nextjs | `SENTRY_DSN` |

## Rückweg
`git revert` der Integrationsdateien, DSN-Variablen entfernen, neu bauen. Ohne DSN keine Überwachung, keine Funktionsänderung.
